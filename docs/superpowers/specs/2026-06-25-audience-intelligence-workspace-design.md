# Audience Intelligence Workspace — Design Spec

- **Date:** 2026-06-25
- **Status:** Approved (design) → ready for implementation planning
- **Route:** `/peton` (replaces the old Peton dashboard)
- **Source mockup:** Claude Design project `728aba11-5eda-4b9c-993a-6c219090d3a0`, file `Audience Intelligence.dc.html`
- **Data contract:** `launch-intelligence/vitality-chew.json` (generated by Codex's launch-intelligence pipeline)

## 1. Goal

Port the "Audience Intelligence" mockup into the Next.js app as a real, grounded product workspace that reads Codex's generated `launch-intelligence/<sku>.json`. It reframes the corpus analysis as a **launch decision tool** for a specific product (Vitality Chew): who the audience is, how to talk to them (message map), the evidence behind each message, and a creative library.

The mockup is the visual spec; the pipeline JSON is the source of truth. Where the two disagree, **the data wins** and the design adapts — consistent with the app's one inviolable rule: *grounded, not generative.*

## 2. Context

- The app (Next.js 16 App Router · React 19 · Tailwind v4) currently serves a static analyst report at `/` (rewrite to `public/dogist-report.html`) and an interactive dashboard at `/peton` (`components/PetonDashboard.tsx`). `/` is the live client-facing surface and is **out of scope** here.
- The existing data pattern is **static JSON import + hand-written TS types** (see `PetonDashboard.tsx:28`). We follow it.
- Codex is building the launch-intelligence pipeline in parallel. It has already generated `launch-intelligence/vitality-chew.json` (the real contract this UI consumes). The Anthropic API is **not** needed for this frontend work; the JSON is pre-generated.

## 3. Locked decisions

| Decision | Choice |
|---|---|
| Placement | Replace `/peton`. Park the old dashboard at `/peton-legacy` (recoverable); remove only after the new views verify. `/` (report) untouched. |
| Scope | All four views: Overview, Messaging Studio, Evidence, Creative. |
| Unmapped panels | Adapt to real data (demographics from `brief.deck_context`, plus an audience-mode breakdown). |
| Message Map | 3×3 board with **mode-tagged cells** (3 value props × their 3 best-fit angles = 9; each cell carries its own audience-mode badge). |
| Grounded extras | Only **Dogist voice in Creative** (voice do/avoid + caption examples). Evidence rail stays faithful to the mockup (comments + "copy this angle"); no added claims-to-avoid panel, no "test this first" callout. |
| Data | Build against the real `launch-intelligence/vitality-chew.json`. No parallel fixture. Transforms adapt the real contract into view models. |

## 4. Architecture & file layout

A **server page** imports the JSON and passes it as props into a **pure client component tree**. This isolates the data source (so multi-SKU later is trivial) and keeps the view logic unit-testable.

```
app/peton/page.tsx                 # server: imports JSON, sets metadata, renders <Workspace data=... />
app/peton-legacy/page.tsx          # server: renders old <PetonDashboard /> (temporary, for verification)

lib/launch-intelligence/
  schema.ts                        # TS types mirroring the REAL vitality-chew.json shape (the contract)
  transforms.ts                    # PURE functions: contract → view models (matrix, signal map, confidence, top voices)
  transforms.test.mjs              # node --test (the repo's existing runner)

components/audience-intelligence/
  Workspace.tsx                    # 'use client' shell: sidebar + topbar + view router + useState
  Sidebar.tsx                      # brand, product switcher, nav, corpus-synced footer
  Topbar.tsx                       # crumb, view title, pipeline indicator, segment chips (messaging view)
  views/OverviewView.tsx
  views/MessagingStudio.tsx        # 3×3 board + Signal Map + evidence rail
  views/EvidenceView.tsx
  views/CreativeView.tsx           # image slots + Dogist voice reference
  ImageSlot.tsx                    # React port of image-slot.js (drag-drop + localStorage persistence)
  workspace.module.css             # SCOPED styling (own palette/fonts) — does NOT touch globals.css
```

Import via the `@/` alias, e.g. `import data from '@/launch-intelligence/vitality-chew.json'`.

## 5. Data contract (the real shape)

Types in `schema.ts` mirror the generated file exactly. Top-level keys:

- **`brief`** — `sku`, `slug`, `active_question` ("How should we talk about the Vitality Chew?"), `launch_timing`, `positioning[]`, `ingredients[]` (`{name, role}`), `claims_to_test[]` (`{id, label, keywords[]}`), `audience_jobs[]`, `brand_guardrails[]` (`{id, text}`), `competitors[]` (`{name, deck_positioning, deck_gap}`), `channels[]`, `trust_constraints[]`, `deck_context` (`{brand_promise, target_insight, brand_essence_statement, audience_context{instagram_followers, tiktok_followers, social_reach, female_share, age_25_34_share}}`), `external_market_context{present:false,…}`.
- **`corpus_summary`** — `posts_analyzed` 370, `comments_analyzed` 97,579, `unique_commenters` 49,478, `high_signal_comments` 15,557, `total_comment_likes` 164,021, `snapshot_note`.
- **`voice_profile`** — `cadence_patterns[]` (`{id,label,description,examples[]}`), `tone_markers[]`, `deck_guardrails[]`, `do_rules[]`, `avoid_rules[]`.
- **`audience_modes[]`** (5) — `id`, `label`, `role`, `evidence_breadth{matched_comments, high_signal_comments, posts, authors, total_comment_likes, top_post_share, high_intent_comments}`, `evidence_quality_flags[]`, `claim_alignment[]`, `key_tensions[]` (`{text, source_type}`), `trust_risks[]`, `representative_quotes[]` (`{id, text, likes, post_url, post_title, signal_score, …}`), `top_posts[]`, `source_cluster_ids[]`, `source_cluster_limits[]` (`{source_cluster_id, risk_flags[], top_post_share}`).
- **`sku_signal_map`** — `mode_matches[]` (`{audience_mode, audience_mode_label, fit_score (0-100), fit ("high"/…), supported_claims[]{claim_id,label,score,fit}, objections[], evidence_quality_flags[], source_cluster_ids[]}`).
- **`message_architecture`** — `active_question`, `interpretation_stages[]` (context_free → launch_context → dogist_voice_translation), `value_props[]` (3) (`{id, value_prop, claim_focus[], angles[]}`). Each **angle**: `audience_mode`, `audience_mode_label`, `dogist_style_angle`, `why_it_resonates`, `language_to_borrow[]` (`{text, source, source_id, why}`), `evidence_quotes[]` (`{id, text, likes, post_url, post_title, signal_score}`), `claims_to_avoid[]`, `validation_prompt`, `source_note`.
- **`trust_guardrails`** — `core_constraints[]`, `sensitive_contexts[]`, `mode_specific_risks[]`, `unsupported_claims_to_avoid[]`. *(Available; not surfaced in first cut per scope.)*
- **`validation_plan`** — `recommended_first_test`, `validation_posts[]`, `learning_loop[]`. *(Available; not surfaced in first cut per scope.)*
- **`evidence_index`** — `audience_comments[]` (25) (`{id, text, likes, post_url, post_title, signal_score, audience_mode, audience_mode_label}`), `dogist_voice_examples[]` (20) (`{text, post_url, reason, voice_pattern_id, voice_pattern_label}`), `evidence_policy[]`.

`brief` and `voice_profile` are embedded in this file, so **one import** powers the whole workspace.

## 6. Design system (scoped)

The mockup is a distinct visual world from the app's terracotta/Courier report. To avoid breaking the report and old dashboard (which depend on `globals.css`), all new styling is **scoped** via a CSS Module + local CSS variables.

- **Palette:** bg `#F6F5F0`, panel `#FFFFFF`, border `#E7E5DD`, ink `#16150F`, muted `#9A968C`/`#6E6A62`, accent blue `#2E9FDD`, "live/synced" green `#3DA85E`.
- **Mode colors:** a stable 5-color palette keyed by `audience_mode` id, defined once and reused everywhere a mode appears (badges, dots, bars, Signal Map). Default assignment (provisional, confirmed visually): `ingredient_scrutinists` `#2E9FDD` (blue), `senior_care_caregivers` `#F2683C` (orange), `picky_dog_pragmatists` `#EDA426` (amber), `wellness_routine_builders` `#2FA98C` (teal), `homemade_diet_optimizers` `#8C6BD8` (violet).
- **Fonts:** Fredoka (display), Hanken Grotesk (body), Space Mono (labels/numbers/eyebrows) via `next/font/google`, exposed as CSS variables and applied only within the workspace.
- The mockup's DC runtime (`<sc-for>`, `<sc-if>`, `DCLogic`, `image-slot.js`, `support.js`) is **rewritten as idiomatic React** — none of it carries over.

## 7. State model

`Workspace` holds client state with `useState`, mirroring the mockup's logic:

- `view`: `'overview' | 'messaging' | 'evidence' | 'creative'` (default `'messaging'`)
- `seg`: selected `audience_mode` id or `null` (filter/highlight)
- `cell`: selected message cell key `"<vpIndex>_<angleIndex>"` or `null`
- `quad`: selected Signal Map quadrant id or `null`
- `q`: evidence search string
- `copied`: transient copy-confirmation flag

Derived render data comes from `useMemo` over the pure transforms in `lib/launch-intelligence/transforms.ts`.

## 8. View specs

### 8.1 Sidebar + Topbar
- **Sidebar:** Dogist brand + "AUDIENCE INTELLIGENCE"; product switcher showing `brief.sku` (single SKU now, structured for many); nav (Overview / Messaging Studio / Evidence / Creative) with counts (modes, 9 angles, `evidence_index` size); footer "Corpus synced · 97,579 comments · @thedogist" + brand line. Counts/labels come from data, not hardcoded.
- **Topbar:** crumb (`WORKSPACE / VITALITY CHEW`), `viewTitle`, a pipeline indicator (Collect→Cluster→Signal→Translate, sourced narratively from `interpretation_stages`), and the 5 audience-mode filter chips (shown in the messaging view).

### 8.2 Overview
- **KPIs** from `corpus_summary` + counts: comments 97,579, audience modes (5), message angles (9), comment likes (164,021).
- **"How the pipeline works":** 4-step method explainer; the interpretation steps reference `message_architecture.interpretation_stages`.
- **"Who's in the audience":** demographics from `brief.deck_context.audience_context` (80% female, 40% 25-34, reach) **clearly labeled "The Dogist deck,"** plus an **audience-mode breakdown** (mode label + `evidence_breadth` bar) — the grounded adaptation.
- **CTA card:** `brief.active_question` → opens Messaging Studio.

### 8.3 Messaging Studio (hero)
- **Message Map — 3×3 mode-tagged board.** Rows = `message_architecture.value_props` (3), each rendered with a VP card (`value_prop` title + essence/claim focus). The 3 cells in a row = that VP's 3 `angles`. Each cell shows: `dogist_style_angle` (the line), an **evidence bar** (the angle's mode `evidence_breadth.high_signal_comments`, scaled to the max across the 5 modes), a **mode badge** (label + color, since columns are not a shared axis), and a **STRONG/TEST tag** + **confidence** (see §9). Clicking a cell selects it for the evidence rail.
- **Segment filter:** the 5 mode chips (topbar) highlight/dim cells whose `audience_mode` matches `seg`. A mode can appear in multiple rows; all matching cells highlight.
- **Signal Map (right rail, 2×2):** a **marked-derived placeholder** built from `sku_signal_map` + `audience_modes` until Codex ships a first-class `signal_map` field. Renders a 2×2 with four labeled, counted quadrants; clicking a quadrant filters the board. The transform is commented `// DERIVED PLACEHOLDER — replace with launch JSON signal_map (coordinate with Codex)` and gated on `data.signal_map ?? deriveSignalMap(...)`.
- **Evidence rail (right):** faithful to the mockup. When a cell is selected: mode + value-prop header, the `dogist_style_angle`, a "N comments support this angle" line, the angle's `evidence_quotes` (real text + author/handle + likes), and a **"Copy this angle"** button (copies `dogist_style_angle`). Empty state: "Top voices" = top `evidence_index.audience_comments` by likes.

### 8.4 Evidence
- Searchable table over `evidence_index.audience_comments`. Columns (real fields): **Comment** (`text`, with `post_title` as secondary context), **Mode** (`audience_mode_label` + color dot), **Signal** (`signal_score`), **Likes** (`likes`). Each row links out via `post_url`. Search filters by comment text; the 5 mode chips filter by `audience_mode`. Footer notes the sample size honestly (e.g. "Showing N of 97,579 — representative high-signal sample").

### 8.5 Creative
- **Hero slot** + **9 angle slots** (one per message-map cell), each labeled with mode + value prop (from `message_architecture`). `ImageSlot` supports drag-drop image → **localStorage persistence** (keyed by slot id). No pipeline dependency.
- **Dogist voice reference** (the chosen grounded extra): `voice_profile.do_rules` / `avoid_rules` and a few real `evidence_index.dogist_voice_examples` (captions + `voice_pattern_label`) so creative stays Dogist-native.

## 9. Confidence / STRONG-TEST derivation (pure transform)

The mockup faked confidence via "mentions ≥ 1100." We derive it honestly per cell:

- Inputs: the angle's `audience_mode` → its `sku_signal_map.mode_matches[mode]` (`fit_score`, and `supported_claims` score for the row's `claim_focus`), plus `audience_modes[mode].evidence_quality_flags` and `source_cluster_limits[].risk_flags` (e.g. `single_post_thread_heavy` penalizes).
- Output: a `confidence` enum (`HIGH` / `MEDIUM` / `EARLY SIGNAL`) and a `STRONG` vs `TEST` tag.
- This lives in `transforms.ts` and is **unit-tested** (thresholds, penalty application, missing-field fallbacks).

## 11. Testing & verification

- **Unit (`node --test`, the repo runner):** `transforms.test.mjs` covers — the board is always 3 rows × 3 cells / 9 angles; confidence mapping from fit + flags (incl. single-post-heavy penalty); top-voices sort by likes; mode-filter highlight logic; derived Signal Map shape.
- **Build:** `npm run build` passes (Next 16 + strict TS).
- **Manual:** per the user's dev-server rules — free port 3000, fresh `npm run build` + `npm run dev`, then screenshot `/peton` across all four views and interactions (cell select, mode filter, search, image drop). Compare against the mockup and `/peton-legacy`.

## 12. Coordination with Codex (integration risks)

- **Source of truth:** `launch-intelligence/vitality-chew.json`. `schema.ts` + `transforms.ts` are the written contract on the frontend side.
- **Signal Map:** consume `data.signal_map` when Codex adds it; the derived placeholder is clearly marked for replacement.
- **Schema drift:** if Codex renames fields, only `schema.ts`/`transforms.ts` change — components consume view models, not raw JSON. A short contract note (this spec §5) is the shared reference.
- **No secrets / API:** this frontend renders from the static JSON only; `.env.local`/`ANTHROPIC_API_KEY` are not required for `/peton`.

## 13. Non-goals (first cut)

- No changes to `/` (report), `/api/dogist-chat`, or the analysis pipeline.
- No multi-SKU routing yet (structure supports it; only Vitality Chew exists).
- `trust_guardrails` panel and `validation_plan` "test first" callout are **not** surfaced (deselected). Data remains available for a later pass.
- No deletion of `PetonDashboard.tsx` in this change.

## 14. Open questions / risks

- Final **Signal Map** axes/semantics depend on Codex's forthcoming first-class `signal_map`; the derived placeholder is intentionally provisional and will be swapped when that field lands.
- The provisional 5-mode color palette (§6) is confirmed during visual verification.
